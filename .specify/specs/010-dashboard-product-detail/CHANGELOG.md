### Rev 5 (2026-06-23) — Debug-mode product-resolution chip on the modal

- Change: Additive contract amendment. Added FR-010 + US2 + AS-025: when spec 022's signed `meals_debug_mode` cookie is effectively verified-on, the Product Detail Modal MUST surface a debug chip / inline panel that exposes the product-resolution chain for the currently inspected item — `tpnc` (when known), `productBlobPath`, winning source for `description` ∈ `apollo | firecrawl | placeholder` and for `image` / `storage` / `preparation` where each is known, and freshness metadata (`product.lastFetched`, `firecrawl.lastFetched`). When debug mode is off, the chip MUST NOT render in the DOM, the rendered HTML, or any reachable client-side payload. The chip's data source is the spec 031 product-resolution panel payload (spec 031 FR-005 / FR-006); the chip MUST be data-equivalent to that panel and MUST inherit the spec-022 OIDC + signed-cookie gate. ### Rev 5.1 (2026-06-23) — Expected-vs-actual productBlobPath in the chip
- Change: Additive on top of Rev 5. Added FR-011 + AS-026: the debug chip MUST additionally surface `expectedProductBlobPath` (derived from the item's tpnc per the spec 021 Key Entities convention `products/{tpnc}.json` — `null` when tpnc is unknown) and `productBlobPathMatch: true | false | null` (boolean comparing `expectedProductBlobPath` to `productBlobPath`; `null` when either side is absent). When `true`, the chip shows `expected: products/<tpnc>.json ✓ match`. When `false`, the chip shows `expected: products/<tpnc>.json ✗ found <actual>`. When `null` (tpnc unknown or path absent), the chip shows `expected: (unknown — tpnc not resolved)` and MUST NOT show a misleading `false`. The data source is the spec 031 Rev 3 product-resolution payload (FR-005 / FR-006 as amended by Rev 3); the chip MUST import the spec-031 matcher helper and MUST NOT hardcode the convention.
- Status after change: Proposed (unchanged from Rev 5 — Rev 4 + Rev 5 + Rev 5.1 must all be verified live before flipping back to Final)
- Rationale: Danny asked on 2026-06-23: "does the debug contain information such as expected blob storage path for product meta data?". The convention from spec 021 Key Entities is `products/{tpnc}.json`. Surfacing the expected path alongside the actual `productBlobPath` with a match flag closes the convention-drift blind spot: today the chip shows only the path that was chosen, leaving drift invisible unless the operator knows the expected-path rule. When the values match, the operator sees a green checkmark; when they don't, the operator sees the actual path inline. When tpnc is unknown, the chip reports `null` (not `false`) — a missing tpnc is a different problem from a wrong path. The matcher is sourced from spec 031 Rev 3; the chip MUST NOT hardcode the convention.
- Implementation impact: `DebugProductResolutionChip` extended to render the two new fields by reading from the spec-031 Rev 3 product-resolution payload. The matcher helper (spec 031 Rev 3 FR-005 / FR-006) runs server-side using the spec 021 Key Entities convention `products/{tpnc}.json`. Unit tests cover match / mismatch / tpnc-unknown / path-absent cases plus a matcher-helper golden test. Production verification: open an item with a matched tpnc + path, confirm `✓ match`; open a drifted-path item, confirm `✗ found <actual>`; open an item with no resolved tpnc, confirm `(unknown — tpnc not resolved)`. Bundle grep invariant: `grep -rn "products/{tpnc}.json\|products/\${tpnc}\.json" /home/hermes/workspace/meals-dashboard --include='*.ts' --include='*.tsx'` returns matches only in the spec-031 matcher helper itself.
- Evidence: Cross-references spec 031 Rev 3 (FR-005 / FR-006 amendment) and spec 021 Key Entities `ProductBlob: products/{tpnc}.json`. Implementation lands on the meals-dashboard `preview` branch (T090..T093); evidence captured in CHANGELOG.md with the coder-profile commit SHA + deploy ID, then status flips from `in_progress` to `satisfied` once production is verified. Spec 010 status stays `Proposed` until Rev 4 (truthful placeholder) + Rev 5 (debug chip) + Rev 5.1 (expected-vs-actual) are all verified live.
