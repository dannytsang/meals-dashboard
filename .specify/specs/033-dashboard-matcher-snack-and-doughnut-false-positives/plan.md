# Implementation Plan: Dashboard Matcher Snack and Confectionery False Positives

Status: Proposed
Feature: 033-dashboard-matcher-snack-and-doughnut-false-positives
Skill: data-science/meals-check

## Summary

Fixes a class of false-positive matches in `tesco_matcher.py` where everyday (non-roast) meals incorrectly accept crisps, doughnuts and similar snack/confectionery products as matched items. The matcher currently uses exact-word singular marker matching (`is_drink_snack`) and grants a protein bonus to any item whose `protein_type` falls back to `vegetarian`/None against a non-animal-protein meal type. Both gaps combined allow `Popchips` and `Pringles` to match `Cheesy mash potato`, `Sea bass + onion rings + wedges`, and `Jacket potato / garlic bread`, and `Tesco White Iced Ring Doughnuts` to match `Sea bass + onion rings + wedges` via the snack product's incidental `rings` substring. Fix is in `tesco_matcher.py` only (guard predicates and one bonus-eligibility gate); regression coverage goes in `test_tesco_matcher.py`; the dashboard cache regenerates from the corrected matcher.

## Risks

- **Risk: stem-match helper false-positives.** A word like `dough` could match `dough`+`'s'` if the helper is naïve. **Mitigation**: helper checks both `word == marker` AND `word == marker + "s"` AND `word == marker + "es"` (orthographic plural forms only); unit tests cover the canonical plurals.
- **Risk: protein-bonus gate over-blocks.** A future meal like `Vegetarian bean chilli` should not get the protein bonus because `vegetarian` is not an animal protein — and the bonus was always meant for animal-protein matches. **Mitigation**: the gate is a true reflection of the existing intent; coverage-status logic at line 766-770 still rewards generic-component matches via `missing_generic_components` from spec 011 Phase 5 work.
- **Risk: cookie dessert regression.** A legitimate `Cookies and cream` meal that previously matched `Tesco Chocolate Chip Cookies 200G` must still match after the fix. **Mitigation**: AS-007 explicitly verifies this; the cookies match is via Tier 1 substring (`cookies` in `cookies and cream`), not via protein bonus, so the FR-003 gate does not affect it.
- **Risk: spec 011 acceptance regressions.** Spec 011's roast-dinner regressions (FR-001 through FR-010) might interact with the protein-bonus gate if a roast-dinner meal happens to have `potato`-type as the meal protein. **Mitigation**: `potato` is not an animal protein so the roast-pork / roast-beef bonus flow (lines 694-710) is unaffected; spec 011's `meal_is_pork_dish` override at line 640 is also unchanged. Run the full `test_tesco_matcher.py` suite to confirm.
